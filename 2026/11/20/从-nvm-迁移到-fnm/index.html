从 nvm 迁移到 fnm

发表于 2026-11-20 分类于 nodejs 本文字数： 2.6k 阅读时长 ≈ 9 分钟

场景：个人 PC 双系统（Windows 11 原生 + Debian），原先都用 nvm 管理 Node.js，现在统一换成 fnm。

一、为什么更换？

2026 年个人机器上 fnm 是更推荐的默认选择，但它不是”必须换”——nvm 依然能用。判断标准是你在意什么：

  • 你在意终端启动速度和切换速度 → 换 fnm（nvm 是 shell 脚本，每个新终端都要 source 一遍；fnm 是 Rust 编译的单文件二进制，启动开销接近 0）。
  • 你在意Windows 原生支持 → 必须换 fnm。nvm 官方不支持 Windows，你现在 Windows 上用的其实是另一个项目 nvm-windows（作者 Corey Butler），它连 .nvmrc 都不读，nvm use 必须手打版本号。这本身就是两套东西、两套行为，长期维护很别扭。
  • fnm 一个工具同时跑 Windows / Linux / macOS，配置语法一致，这是你双系统最实际的收益。
  • 你已经有大量 .nvmrc → 无损迁移，fnm 原生读 .nvmrc 和 .node-version。
  • 如果你需要”跟着 package.json 把 node 和包管理器版本一起钉死给团队” → 那不是 fnm 的活，看 Volta 或 mise。fnm 只管 node 版本。

nvm vs fnm 对照

维度 nvm（POSIX）/ nvm-windows fnm
实现 Shell 脚本 / Go Rust 单文件二进制
终端启动开销 数十~上百 ms < 5 ms
Windows 原生 否（要装另一个项目） 是，同一套命令
读 .nvmrc 是 / Windows 版否 是
读 .node-version 否 是
cd 进目录自动切换 需手写 hook --use-on-cd 内置
支持的 shell bash/zsh/sh bash/zsh/fish/PowerShell
管 npm/pnpm 版本 否 否（交给 corepack）

一句话取舍：nvm 是”最多教程、最广认知”的老牌方案；fnm 是它的事实标准替代品（同命令、同 .nvmrc、更快、跨平台）。只有”团队级可复现构建”才需要考虑 Volta/mise。

二、迁移前必做：先记账（两个系统都要做）

fnm 不会接管 nvm 已装的 node，版本要重建，全局包要重装。先记下来，否则删完就查不到了。

Windows 上如果多个 node 版本各有一套全局包，逐版本切换后各跑一次 npm ls -g --depth=0。

三、Windows 11：卸载 nvm-windows

nvm-windows 是用符号链接（C:\Program Files\nodejs）指到当前版本目录的方式工作的，卸载不干净就会残留一个假的 node 命令，装完 fnm 后到处报错。按顺序做：

1. 执行官方卸载程序

  • 打开「设置 → 应用 → 已安装的应用」，搜 NVM for Windows，点卸载；
  • 或直接运行 %APPDATA%\nvm\unins000.exe。

2. 删残留目录

路径 说明
%APPDATA%\nvm（即 C:\Users\<你>\AppData\Roaming\nvm） nvm 本体 + 所有 node 版本
C:\Program Files\nodejs nvm 建的符号链接目录，必须删
C:\Users\<你>\AppData\Roaming\npm 旧全局包的 bin 目录（可选清）

九、踩坑清单

  1. Windows 上没删 C:\Program Files\nodejs → node 命令仍指向旧版本或直接损坏。装 fnm 前必须 where.exe node 无输出。
  2. 改了环境变量不重开终端 → 看起来”装成功但命令找不到”。winget 装完、改完 Path，全部重开终端，必要时重启。
  3. PowerShell profile 写错文件 → PowerShell 7 的 $profile 是 ...\Documents\PowerShell\Microsoft.PowerShell_profile.ps1，Windows PowerShell 5.1 是 ...\Documents\WindowsPowerShell\...。你在 pwsh 里配的，cmd/旧 PS 里不生效，属正常。
  4. 全局包全部消失 → 正常现象。全局包按 node 版本隔离存放，fnm use 到新版本后要重新 npm i -g。迁移前用 npm ls -g --depth=0 记好清单。
  5. .nvmrc 读到了但不切换 → 检查 eval 行有没有 --use-on-cd；monorepo 再加 --version-file-strategy=recursive。
  6. 两个系统共用一份 dotfiles 仓库 → 用 --shell bash / --shell powershell 区分，别把 PowerShell 那行塞进 .bashrc。
  7. 想同时管 Python/Go → fnm 只管 node，这类需求看 mise，别硬塞给 fnm。
  8. 别用 sudo npm install -g → 一旦用 root 装全局包，node 在用户目录的权限模型会被破坏，后续 fnm 切换版本会出现奇怪报错。
